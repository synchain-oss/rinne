# 探针日志格式（v1）

探针构建写出、`analyze-probe.py` 严格读入的 CSV 契约。分析器拒绝任何取值不合本文的行（退出码 2），所以探针一侧照本文写，不必猜分析器的宽容度。机读版本是 `analyze-probe.py --spec`，`checks.d/probe-analysis` 把本文与它对拍：行类型及其列名与列序、H 的枚举取值、事件名、全部 case、variant、guard、阈值与取值上界，本文漏列、改序或写错任何一项都会判红。事件参数的类型与含义不自动对拍，由 `fixtures/` 的严格解析兜底。合成样例在 `fixtures/`，由 `probe_synth.py` 生成。

## 文件

- 每个探针实例（一个 Input 或一个 Output）一个文件：`probe-<role>-<pid>-<tok4>.csv`，`role` 为 `I` 或 `O`。目录位置见探针构建的说明；分析器只读目录里 `probe-*.csv` 与 `compare-*.csv`，别的文件忽略。
- 纯 ASCII，行尾只能是 `LF`（出现 `CR` 判格式错）。字段用逗号分隔，没有引号与转义，所以任何字段都不得含逗号；文本字段一律百分号编码（见「文本字段」）。
- 每行写完才算一行。最后一行没有换行视为写到一半被截断，分析器丢掉它（并记下丢了几个字节），把该实例判为未正常收尾（A8 不通过），文件其余部分照常解析，不进「不完整的日志文件」。探针一批行一次 `write` 再 `flush`，不是逐行落盘；整机崩溃时这一批可能只落下前半截，残缺的末行就是这么来的，崩溃后补零的末尾（长度已更新、数据还是零）同样没有换行，按同一条处理。只认「没有换行结尾」这一种残缺：有换行结尾却字段残缺的行不是写到一半，是内容损坏，仍是格式错误。文件是空的、只有写到一半的首行、或没有合法的 `H` 行（文件头魔数行与 `H` 行没写完，没有角色也没有 pid），同样不算格式错误：这是实例刚创建就崩溃的样子，分析器记入 A8 不通过，其余文件照常分析。非法取值才是格式错误，整次分析退出码 2。
- 第 1 行是魔数 `rinne-probe-log,1`，第 2 行是唯一的 `H` 行，之后是下表的各类行，`Z` 行出现后不得再有内容。
- 块与事件归属于哪个 `C`，分析器按时间戳（`mono_ns`、`t_ns`）算，不看它们在文件里的先后；所以不同类型的行、不同线程写出的行在文件里交错是允许的：`C` 与事件由别的线程排队，音频线程自己的事件、`B`、`S` 由落盘线程每一轮按固定的顺序写出，它们在文件里的先后与时间戳不必一致。**`B` 行是例外，也是唯一有顺序要求的**：同一个实例的块在任一时刻只有一个生产者（宿主的处理线程；ASIO-Guard 换线程时也是先后接力，不并发）、经先进先出的环交给落盘线程，所以 `B` 行按文件顺序 `seq` 与 `call_seq` 都严格递增，文件顺序就是 `seq` 顺序。分析器对不严格递增的 `B` 行（重复、回退，隔着别的行也一样）判格式错（退出码 2，消息只带文件序号与行号），所以序号缺口、实例开头缺的块、尾部丢块都直接按文件顺序算，不再按 `seq` 重排。

## 行类型

第一列是行类型，其余列按表中顺序。整数一律十进制无前导零（`0` 除外）；`bool` 为 `0` 或 `1`；时间 `t_ns` 与 `mono_ns` 是同一个单调时钟的纳秒数。

| 类型 | 含义 | 列 |
|---|---|---|
| `H` | 实例头，恰好一行，必须在第 2 行 | `role` `format` `host_kind` `os` `arch` `pid` `ppid` `tok4` `build` |
| `C` | 开始一个测试格（case 上下文），之后到下一个 `C` 之前的块与事件都属于它；`C` 行的 `t_ns` 不得晚于该窗口第一块的 `mono_ns`（先取时间戳、写 `C` 行，再打开块记录），否则那块成孤块、挡 F1 | `t_ns` `case` `variant` `buf` `guard` `sr` |
| `B` | 逐块记录，只在「开始记录」窗口内写 | `seq` `call_seq` `role` `n` `n_decl` `host_ns` `host_ns_valid` `playing` `nonrt` `bypassed` `mono_ns` `thread` `m` `w` `off` `rs` `d` |
| `S` | 1 Hz 摘要，窗口外也写 | `t_ns` `blocks` `dropped` `max_n` `resync` `trips` |
| `E` | 事件 | `t_ns` `name` `a` `b` |
| `Z` | 正常收尾，实例析构时写 | `t_ns` `blocks_total` `dropped_total` |

`H` 的取值：`role` ∈ `I` `O`；`format` ∈ `vst3` `au`；`host_kind` ∈ `cubase` `luna` `other`；`os` ∈ `win` `mac`；`arch` ∈ `x64` `arm64`；`pid` 与 `ppid` 是不超过 4294967295 的整数；`tok4` 是 4 位小写十六进制；`build` 是 8 位小写十六进制（提交散列前 8 位）。

`C` 的取值：`case` 与 `variant` 取下面两张表里的值；`buf` 是缓冲区大小（样本，不超过 65536）或 `-`；`guard` ∈ `off` `low` `normal` `high` `na`（ASIO-Guard 档位，不适用写 `na`）；`sr` 是不超过 768000 的采样率。

**格与同键重复。** 同一个 `(case, variant, buf, guard)` 叫一个「格」，In 与 Out 两端对同一个格各写一段，分析器靠这个键把两端配起来。一个实例可以在一个文件里连续写很多格（每格一个 `C` 行）。同一个键下不得出现第二份记录：某格做坏了，就记下来，等该实例整体重采一遍（关掉插件再开，生成新文件），并把旧文件挪走。分析器遇到同键重复（`rip`、`freeze`、`dup`、`undo`、`twoproj` 除外，这几种会多出实例是预期内的）时不会静默挑一份，而是把相关判据判为数据不全、在输出的「提示」里列出，并让 F1 不满足。

**快照。** 配对、后端、状态恢复这类事件往往发生在用户选 case 之前。分析器把第一个 `C` 行之前的事件归为实例级，A5 与 A9 会同时看实例级与分段内的事件。为了让每一格自含，探针在每个 `C` 行之后立即补写一遍当前状态的快照：`prepare`、`backend`、`paired`、`shm_denied`（如发生过）、`set_state`（如发生过）、`track_props`。从未发生过的就不写，只有 `track_props` 例外：从未送达则写 `a` 与 `b` 都为空的一条。原事件照常在发生时写，快照是**额外的**事件，它的 `t_ns` 是补写的时间；A9 按 `t_ns` 比较 `set_state` 与 `paired` 的先后，所以只写快照而不写原事件的实现会让顺序失真。第一个 `C` 之前出现的 `B` 行无法归入任何格，分析器计数、列入「提示」并让 F1 不满足，所以探针应当先取时间戳、写 `C` 行，再打开块记录：`C` 行的 `t_ns` 不得晚于该窗口第一块的 `mono_ns`。违反时分析器不中止整次分析：那块被计为孤块（落在第一个 `C` 之前），或被归进上一格，前者会列入提示并让 F1 不满足。

`B` 的列：

| 列 | 含义 |
|---|---|
| `seq` | 实例级的块序号，只对实际写出的 `B` 行递增，窗口之间不归零、也不为没有记录的回调递增；按文件顺序严格递增（见上，不递增的 `B` 行是格式错）。丢一条记录就在 `seq` 上留下缺口，分析器据此判「数据不全」 |
| `call_seq` | 全局回调顺序号（共享内存头里 `fetch_add` 得到），按文件顺序严格递增，用来还原 In / Out 的交错 |
| `role` | 必须与 `H` 的 `role` 相同 |
| `n` `n_decl` | 本次回调样本数；`prepare` 时宿主声明的最大块长；都不超过 1048576 |
| `host_ns` `host_ns_valid` | 宿主给的时间戳及有效位；无效时 `host_ns` 写 `0` |
| `playing` `nonrt` `bypassed` | 走带状态；是否离线渲染；是否走了 `processBlockBypassed` |
| `mono_ns` | 本块开始时的单调时钟 |
| `thread` | 线程标识的 8 位小写十六进制散列，不是原始线程号 |
| `m` | 读头与期望位置的偏差（样本，有符号），稳态应恒为 0。Input 与 Output 都写；Output 写自己的写位置与期望位置的偏差 |
| `w` `off` | `w` 是单调累计的帧计数（与 IPC 的单调写头一致，不对环容量取模），相邻两块的差应等于上一块的 `n`，旁路时同样；`off` 是读头相对写位置的偏移（样本，有符号）。Output 的 `off` 写它的写位置相对时间线的偏移。稳态下 `off` 恒定，分析器对两端都这样要求。`m`、`w`、`off` 的绝对值都不超过 1099511627776 |
| `rs` | 本块内发生的重同步次数（Input 一侧计，Output 写 0） |
| `d` | 当前生效的环路延迟 D（样本，不超过 2147483648） |

`S` 的列：`blocks` 是累计记录块数，`dropped` 是累计丢弃数，`max_n` 是见过的最大块长，`resync` 是累计重同步，`trips` 是累计安全跳闸（Panic 除外）。`S` 行应由探针自己的日志线程每秒写一条，不要依赖宿主的消息线程；若实现上依赖它，宿主在导出、载入工程、扫描插件时长时间不跑消息线程，摘要就会出现长间隔。分析器把这种情形报成「摘要间隔超限」，与「日志没有收尾」分开说，阈值 5 s 是 1 Hz 摘要的 5 倍，足以容忍偶发抖动，又远短于一次真正的卡死。

丢弃一律要计数：任何丢记录的路径都要增加 `S` 的 `dropped`。分析器据此把受影响的格按数据不全处理：`seq` 缺口落在哪一格就是哪一格，没有缺口可定位时整个实例的各格都按数据不全，并在「提示」里说明。缺口落在第一个 `C` 行之前的块之间（两头都是孤块，或第一个块就是孤块、缺在它之前）的，不归任何格：这些块本来就不在任何格里，提示里单独报个数，也不算「没有缺口可定位」；探针报告的丢弃数全是这类缺口时，各格不因此按数据不全处理（孤块本身仍挡 F1）。

`variant` 取值，`-` 表示不区分。**规则按 (case, variant) 查表，不按 variant 单独查**；表外的组合（例如 `CB-01` 配 `deactivate`）在解析时判格式错，所以每个 case 允许哪些 variant 就是下面这张表。一格要不要两端成对、各至少 32 块，取决于它喂给的判据是否需要两端的稳态块数据，而不是按 case 一刀切；分析器读同一张表（`--spec` 的 `rules`），run-checks 逐行对拍。

- 类别 1「成对满块」：两端各恰有一个实例、各至少 32 块，缺了判数据不全。A1 按 case 判（`CB-01`、`CB-03`、`LU-03` 里除 `toggle` 外的每一格都进 A1，variant 叫什么都一样）；`CB-10` 的 `bufchange` 只喂 A4，不喂 A1 与 A7，因为中途换缓冲后 `m` 与 `off` 本来就会变。A4 与 A7 的「通过」必须至少有一个类别 1 的格得出结论。
- 类别 2「各自证据」：不要求成对和块数，但「不要求」不等于「没数据也算过」，每格必须有表里写的证据，一条都没有就判数据不全。这类格的证据不挂在 A 编号下，而是列在输出的「格观察」里；它们对 A4 只能给不通过或说明，不能单独撑出通过。`CB-05` 在 F1 里，所以它的格观察数据不全会挡住 F1。
- 类别 3「只记录」：不阻断，只留一条说明。
- `dup`、`undo`、`twoproj`、`rip`、`freeze` 允许同键多对实例，每个实例都要有证据：一个配好的实例不能掩盖没配好的。F1 的同键重复只看 F1 所列 case 里类别 1 的格。

## 文本字段与隐私

- 唯一允许携带人写内容的字段是 `track_props` 的 `a`（轨道名），必须百分号编码：保留 `A-Za-z0-9._~-`，其余字节写成 `%XX`。编码前至多 200 字节，超出的部分由探针在 UTF-8 字符边界截断后再编码；分析器对仍然超长的轨道名也只是截断到 200 字节、不判格式错（它只用于比较和算散列）。原始 CSV 因此可能含轨道名，视为私有数据，不进公开仓。
- 其余字段都是整数（带上界）、固定枚举或十六进制，没有路径、用户名、主机名的位置；`thread` 是散列。探针不得把这些信息塞进任何字段。
- 分析器的输出不含这些信息：轨道名只给 `same` / `different` / `unknown` 与一个 8 位散列（带每次运行随机的盐，只用于同一份报告内比较）；格式错误只报文件序号、行号和固定的列名；内部错误只报固定的一句话，不打印 traceback；全文再过一遍路径、用户名、主机名的兜底清洗，运行时可以用 `--redact <词>`（可重复）补充要清洗的词，例如另一台机器的用户名与主机名。输出固定为 UTF-8。

## 导出比对文件

`compare-<任意>.csv`，第 1 行是表头 `case,variant,bit_exact,residual_dbfs,head_residual_dbfs,lag_samples`，其后每行一次 `rinne_nulltest compare` 的结果，由人抄入：`case` 与 `variant` 同上，`bit_exact` 为 bool，两个残差是 dBFS 小数或 `-inf`，`lag_samples` 是有符号整数。`bit_exact` 为 1 时残差必须是 `-inf`，反之亦然，否则判格式错。`head_residual_dbfs` 是开头 2 s 单列的残差，只报告、不参与判定。

每个 case 需要的行：`CB-04` 需要 variant 为 `export-offline` 的行（离线对实时的比较）；`LU-04` 需要 `export-offline` 或 `bounce` 的行。其余 variant（`freeze`、`rip` 等）的行只作记录。参与判定的行里，`lag_samples` 不为 0 判不通过：错位的两份导出对齐之后再比较会掩盖问题。

**A1 的 Out 端起播停顿。** Out 的 `off` 是 `w` 减去宿主时间线。Cubase 起播后头几块里宿主时间线停住不走（或只走一部分），`w` 却照常前进，`off` 因此在每段播放的开头变几下，之后恒定（现场最长一次 56 ms、42 块，64 样本缓冲）。所以 Out 端按播放段判：播放段是连续的 `playing` 为 1 且 `bypassed` 为 0 的块，停播或旁路把一段截断。每段从第一块到 `off` 最后一次变化的那一块算停顿，停顿里每块的 `off` 只增不减、且增量不超过这一块 `w` 的增量（即派生时间线 `w - off` 不后退、也不比 `w` 走得快），停顿不超过 120 ms（常量 `A1_STALL_MAX_NS`，取现场最长一次的约 2 倍）；停顿之后 `off` 恒定，各段停顿之后的 `off` 彼此相等。停顿超限、停顿里 `off` 回退或时间线后退、停顿之后 `off` 不止一种，都判不通过。**In 端不放宽**：`m` 恒为 0、首块之后 `rs` 为 0、`off` 恒定；Out 端的 `m` 与 `rs` 也不放宽。格观察逐格给出 Out 端最长的停顿（ms 与块数）和上限。

**A2 的切换点。** 宿主不通知监听键与录音使能键（VST3 没有这类通知），所以 `monitor_toggle`、`arm_toggle` 实际从不出现。ASIO-Guard 开着时，监听或录音使能会把这条轨在预取（宿主线程池，现场约 32 个线程、几乎每块换一个，块长 512）与实时（专用线程，块长 256）之间挪，B 行的 `thread` 散列随之变化。逐块比较「相邻块的 `thread` 是否不同」会把线程池内部的轮换全数成切换（现场按键 12 次，这样数出 22 次），所以改按处理形态数。分析器取「显式事件 ∪ In 端处理形态的变化点」为切换点：

- 处理形态按 `seq` 排好的 In 端块来划。先把块切成连续同一线程的段；一段的时间跨度（首尾块的 `mono_ns` 之差）不短于 250 ms（常量 `A2_REGIME_MIN_NS`）的，本身就是「专用线程」形态；其余的段（线程来回换得太快，哪个线程都占不满 250 ms）连成一片，这一片里出现的线程不少于 3 个（常量 `A2_POOL_MIN_THREADS`）就是「线程池」形态，否则以这一片用到的线程集合为形态。线程池内部的轮换不算切换；两个专用线程之间的 A→B 算一次。
- 迟滞：一种形态要持续 250 ms 才算数，更短的并进相邻的形态、不算一次切换（现场实时线程切回预取之前有 5 块跑在另一个线程上、不到 1 ms，就是这样被并掉的）。250 ms 取在现场两个数之间：线程池里同一线程连着出现的最长一段 21 ms，实时线程一次占 3.0 s 以上。
- 切换时刻取新形态第一块的 `mono_ns`，窗口起点取它之前的一块（见下）。两种形态之间夹着被迟滞丢弃的杂散段时，杂散段不当切换点，切换时刻仍是新形态的第一块，之前的一块是杂散段的末块。显式事件前后 2 s 内的形态变化与该事件算同一次，不重复数。
- 推断出的切换之后 2 s 内又出现的形态变化并入这一次，不单独算（宿主线程池调度、用户按得比窗口还快，都分不开）；说明里写出并入了几次。
- 每次切换的窗口从切换之前的最后一块算起（切换瞬间旧状态下最后一块的重同步也算这一次），到切换后 2 s 为止；显式事件与推断的切换一视同仁，显式事件的窗口也从事件之前的最后一块算起。只有显式事件（宿主亲口报的）会截断前一个窗口，推断出的切换不截断。窗口按 `mono_ns` 排好序后用二分取，不为每个切换点扫整段。
- 块长 `n` 的变化只作旁证，不算切换（稳态下块长也会抖）：说明里写「其中 k 次伴随块长变化」，指切换点前后各 2 s 内最常见的块长不同的切换有 k 次。一格里处理形态没有变化、也没有显式事件，判数据不全，原因写明处理形态没有变化（ASIO-Guard 关着时监听可能不改处理线程）。

其后的判据照旧：每次切换后 2 s 内重同步不超过 1 次、`d` 不变、窗口块数够、总数够 10 次；重同步超限或 `d` 变化是不通过，与次数对不对得上无关。**推断出来的切换不能单独撑出通过。** 形态变化不一定是用户的操作，宿主的线程池在稳态下也会换线程，和按键分不开。所以现场要用 `--toggles <case>:<次数>`（可重复，`<case>` 取 `CB-02` 或 `LU-03`，同一个 case 只写一次）填上实际按了几次，分析器数出的切换次数（显式加推断）与它相差不超过 1，才算数；没填、对不上都判数据不全，说明里写明原因。切换点里有推断的，这一格里出现的处理形态还不能多于 2 种（线程池预取与专用线程实时，常量 `A2_MAX_REGIMES`）：多于 2 种更像线程池调度，拿到一份真实的形态分布之前不据此通过。给了 `--toggles` 时，纯显式事件的次数也要对得上；没给时，显式事件（宿主亲口报的切换）照常通过。结论文字写明「按处理形态切换推断」，并分开给出显式与推断的次数。

残余限制：宿主线程池恰好只在两个形态之间切换、每次间隔不短于 2 s、次数又与现场填的次数相差不超过 1，仍会通过。这一步靠操作者如实填现场次数，机器分不出；「至多 2 种形态」也只是预取与实时两种的假设，只当保守的上限。实时阶段若在两个线程之间逐块轮换、哪个线程都占不满 250 ms，会和线程池并成一种形态，按没有变化处理（数据不全，不会误通过）。

**只数本段内的事件，停用事件还要落在块流中断里。** 类别 2 的本格证据只数本段里的事件，本段是本格 `C` 行到下一个 `C` 行（或文件尾）之间。`smart` 的 `ping` 条数与 `deactivate`、`disable-track` 的停用事件都这样数；第一个 `C` 行之前的实例级事件不算，免得第 0 步的 Ping 或更早的停用事件替这一格作证。JUCE 的 VST3 包装层把 `setProcessing(false)` 转成 `reset()`，所以探针记 `reset`、不记 `set_processing`：`set_processing`（a 为 0）、`reset`、`release` 三者各自都算停用证据，输出里写明是哪一种。但这三种事件本身不带「用户停用了插件」的信息：宿主起播时会 `reset`，实例析构时 `release` 也会写。所以停用事件还要和块流对上：清单让用户把插件停用约 5 s，停用期间实例不再收到回调，块流里留下一段中断。事件要落在这样的中断里才算：

- 实例自己有块：事件落在它的某一次块间隔里，间隔不短于 1 s，前后都有块；位置在间隔的前半，可以比间隔前的最后一块早 250 ms（事件与块是不同线程取的时间戳）。起播的 `reset`（块流刚开始、没有中断）、析构的 `release`（最后一块之后没有块）、间隔末尾的 `reset` 都不算。
- 实例整段没有块（一直停用）：本格另一端的块流在事件前后都至少延续 1 s。
- 有停用事件、却都不在中断里：判数据不全，说明里写出各端最长块间隙，提示是起播的 `reset`、析构的 `release` 不算停用。

残余限制：宿主在静音时也可能调 `setProcessing(false)`，中断里的 `reset` 仍是偏宽的证据，要结合现场记录看；停用不足 1 s 的操作留不下合格的中断，会判数据不全，重采时按清单停用 5 s。

**短命克隆实例。** 没有 `C` 行、文件里所有带时间戳的行首尾相差不到 2 s 的实例，是宿主为 Render in Place 或 Freeze 临时建的克隆，来不及写第二条 1 Hz 摘要。A8 对它们只记一条说明（写明实例与时长），不判数据不全；没有收尾（疑似崩溃）的仍判不通过。**跳闸只记在摘要行里，这些实例没有摘要行，所以跳闸与卡死对它们无从判断**，A8 的通过不替它们担保这一点。首尾相差 2 s 以上的无 `C` 行实例不在此列，摘要行不足 2 条判数据不全。输出的「附加记录」另列它们的个数与时长：它们没有 `C` 行，`rip`、`freeze` 格的实例数里数不到。有 `C` 行的实例，规则不变。

**A7 的配对与 toggle 格的回退。** `call_seq` 是同一进程里所有探针实例共享的回调计数，同一次宿主回调的 In 块与 Out 块，`call_seq` 之差是个固定的小整数（现场每一格都是 Out = In + 1：链首的 In 先被调用）。先开窗的一端会多出若干块，把排好序之后相邻的 I/O 两两配对会整体错开一位。分析器改为：给每个 In 块找 `mono_ns` 上最近的 Out 块（一个 Out 块只配给离它最近的 In 块），这些最近邻对的 `call_seq` 差（Out - In）取众数，只按这个差用 `call_seq` 精确配对。配对只用 `mono_ns` 与 `call_seq`，不看 hostNs（A7 要判的就是两端 hostNs 是否相等）。差为正是 In 先于 Out，为负是 Out 先于 In（错放），说明里照实写方向。差的绝对值超过 16（常量 `A7_SHIFT_MAX`，现场是 1；同进程多对实例交错时差会变大，取 16 留余量），或众数只占最近邻对数的 90% 以下（常量 `A7_SHIFT_SHARE_MIN`，现场每一格都是 100%），说明两端不在同一个计数器上或先后不稳，判数据不全。

toggle 格（variant 为 `toggle`、case 属 A2）里，ASIO-Guard 切换时宿主的 hostNs 会回退（现场最大一次 7.3 s，两端值相同）。A7 用与 A2 同一套切换点，落在切换点前后各 500 ms 内的回退（常量 `A7_TOGGLE_ZONE_NS`；现场的回退在切换点前 22 ms 到后 9 ms 之间，0.5 s 是记录的上界）容忍并计数，说明里写出次数与最大回退；窗口外的回退照常算非递增，两端不等不放宽。**推断出来的切换点要 A2 确认过才给容忍**：显式事件是宿主亲口报的，一律给；按处理形态推断出来的点可能只是线程池调度，只有这个 case 的切换次数已被 A2 确认（与 `--toggles` 的现场次数相差不超过 1、处理形态不多于 `A2_MAX_REGIMES` 种、次数不少于 10）才给。没给 `--toggles`、次数对不上、形态多于 2 种时，推断的点不给容忍，这些点前后的回退照常算非递增（显式事件的容忍不受影响），说明里写明有几个推断的点没有经 A2 确认、有几次回退本会落在它们前后，以及怎样才算确认；确认了的，说明里写明是由 A2 按哪个 `--toggles` 次数确认的。非 toggle 格没有切换点，一律不放宽，格里多余的 `monitor_toggle` 事件也不开容忍窗口。

**切换次数的对账是整个 case 的性质，由主会话算一次。** `--toggles` 填的是整个 case 的现场按键次数，不是某一段的；确认（与现场次数相差不超过 1、形态不多于 2 种、次数不少于 10）也就是对整个 case 下的结论。分析器在主会话里对每个 case 算一次对账结论，A2 拿它出结论，A7 拿它判断推断的切换点能不能给容忍，两处用同一份。`--exclude` 的影子判定（见下）沿用这份结论：只含被排除的段的计数必然对不上整个 case 的现场次数，拿它去对会把被排除的 toggle 格的推断点一律当成没经确认，切换造成的 hostNs 回退就成了「被排除的段本来就不通过」，`--exclude` 也就拿不掉这样的格。影子里 A2 不再对账次数（对账只会产出数据不全或相符的说明，不会让逐格的判定变成不通过；留着只会把整场的现场次数误记到被排除的段名下），逐格的判定（每次切换后重同步、`d`）照旧。主会话对这个 case 没有结论可沿用时——一个 toggle 格都没有（整个 case 的切换格都被排除了），或留下的格里一次切换都没数到——影子才用被排除的段自己的计数对账：此时 `--toggles` 说的只可能是这些段里的按键。沿用确认不等于放过真问题：窗口外的回退、重同步超限在影子里照样不通过。

**但处理形态数是逐段的性质，沿用之前要先核。** 主会话的确认只说明留下的格里处理形态不多于 2 种（`A2_MAX_REGIMES`），不说明被排除的格也是。被排除的 toggle 格自己出现 3 种以上处理形态时，更像线程池调度（`A2_MAX_REGIMES` 本来要拦的就是这种），在影子里也不能当成「已确认」。所以影子会话沿用主会话的结论之前，先用被排除的段自己的切换点统计（`toggle_counts`）核一遍形态数：不多于 2 种才沿用；多于 2 种就不沿用，该 case 退回被排除的段自己的对账（形态多于上限，对账只会是数据不全），推断的切换点得不到容忍，其前后的 hostNs 回退照常算非递增，A7 在影子里不通过，记进 `excluded_fail`。这样一个本该不通过的段，不能靠 `--exclude` 拿掉。这个核查只影响推断点的容忍：被排除的格形态虽多、hostNs 却没有回退时没有东西要容忍，A7 照常通过；A2 在影子里只判逐格的重同步与 `d`，形态多于 2 种本身只是数据不全，排除是合法的。形态数的口径与主会话一致：一个 case 里被排除的 toggle 格取最大值。

**`--crashed`：整机崩溃的标注。** 整机蓝屏、断电时，所有在跑的实例都来不及写收尾行，这不是插件崩溃，却会让 A8 判不通过。`analyze-probe.py <目录> --crashed <文件名>`（可重复）由人工标注「这个实例的日志因整机崩溃中断」：被标注的实例没有收尾行不再计为插件崩溃，A8 写一条 NOTE（实例序号与角色），报告开头加一行醒目提示「是否确属整机崩溃请人工确认」。其余问题照常判：摘要间隔超限、跳闸、摘要行不足都仍然判。整机崩溃常在文件末尾留下写到一半的一行（没有换行结尾）：这样的文件照常解析，残缺的末行丢掉，`--crashed` 照样认，A8 的 NOTE 写明该实例「末行没有换行结尾，已丢弃 N 字节残行」。只认这一种残缺：文件头（魔数行、`H` 行）都没写完的文件没有角色和 pid，什么都分析不了，也分不清是整机崩溃还是插件刚创建就崩溃（A8 正是要抓这个），进「不完整的日志文件」，`--crashed` 不认它（退出码 5），A8 照样不通过；中间的行损坏、末行有换行结尾却字段残缺是格式错误（退出码 2），`--crashed` 不放宽。被标注的实例其实有收尾行（它是正常结束的，不是被整机崩溃截断的）、文件不存在、同一个文件写两次，都按参数错误处理，退出码 5。输出不回显文件名（同 `--exclude`）；`--json` 的 `crashed` 只给实例序号与角色。

**CB-05 禁用轨道：实例被替换。** Cubase 15 的 Disable Track 会销毁插件实例（`get_state`、`release`、`destruct`），Enable 时在同一个进程里新建实例（新日志文件，没有 `C` 行：`set_state`、`prepare`，约 0.3 s 后 `paired`）。旧实例没有「块流中断」可言，所以这一格的证据多一种：本段内旧实例写了 `destruct`，同 pid、同角色、在它析构之后才出生的新实例，在 15 s 内（常量 `REPLACE_WINDOW_NS`；清单让用户停用 5 s，现场 7.6 s 后 `set_state`、7.9 s 后 `paired`，取约 2 倍）出现 `set_state`，并在同一时限内（从旧实例析构起算）出现 `paired`；写了 `destruct` 的每个旧实例（In、Out 各自）都要有这样的新实例。块流中断里的停用事件仍然优先；新实例没有出现、超时或没有配对，判数据不全并写明。只对 `disable-track` 认实例替换，`deactivate` 不认。格观察另列替换耗时（析构到 `set_state`、到 `paired`）与是否恢复配对。

**`--exclude`：排除误记的段。** 现场点错了格（例如面板默认的 Case 被误记）时，不必整节重采：`analyze-probe.py <目录> --exclude <文件名>:<选择子>`（可重复）把那一段整段拿出判据。文件名是日志目录里的 CSV 文件名，只用来找文件；选择子是该文件里 `C` 行的序号（按文件里出现的顺序，从 1 起）或 `C` 行的 `t_ns`，两种读法可能指向不同的行时写 `#3`（序号）或 `t=3`（`t_ns`）。In 与 Out 各一份文件，一格误记要在两个文件里各排除一次；只排除一边，另一边仍留着，这一格还是数据不全。同一个 `C` 行指了两次（序号与 `t_ns` 两种写法也算）按错误处理。被排除的段不进判据，输出的「已排除的段」（`--json` 的 `excluded`）只列选择子原文、实例序号、角色、格和 `C` 行序号，**不写文件名**（文件名可能带用户自己加的字，也就不用 `--redact` 去补）。

- 只拿得掉数据不全的段，拿不掉不通过的段。被排除的段会单独按「若计入」再判一遍，本来会不通过的项照样记不通过，输出里写明（`--json` 的 `excluded_fail`）：误记的段里 A1 不通过，排除它不能让 A1 变绿。不论主会话里这一项是否已经不通过，被排除的段若计入会不通过就记进 `excluded_fail`；只有主会话里这一项不是不通过时才改写结论与说明。这一遍只算由被排除的段本身导致的失败：A3（读导出比对行，不属于任何段）与 A8（读每个实例的收尾行、摘要与跳闸，是实例级的，记不到某个 `C` 行的段上）读的是整场的数据，别的实例跳闸、比对不过会让影子会话里的它们也不通过，却与被排除的段无关，所以这两项不参与这一遍（常量 `SHADOW_SESSION_WIDE`）；它们在主会话里本来就读全部输入，排除一个段不会让它们少看任何东西。其余判据只读段（格）里的块与事件，仍按被排除的段单独判；唯一读整场口径输入的是 `--toggles` 的对账（A2 的次数、A7 对推断切换点的确认），它是整个 case 的性质，影子沿用主会话的结论，见上「切换次数的对账」。归给被排除的段的缺失块序号，在这一遍里同样让那一段按「有序号缺口」算（数据不全，不是不通过），所以带丢块的误记段不会被当成不通过。
- 缺失的块序号按所属的段归属。探针每个块（写出的与丢弃的）都占一个 `seq`，1 Hz 摘要里的「累计块数加累计丢弃数」就是那一刻已占用的 `seq` 个数；取 `C` 行之前最近一条摘要的这个数作为该格窗口开始前已占用的个数，缺失的序号落在谁的窗口里就归谁。归给被排除的段的不计入判据（主会话里），归给未排除的段的让它数据不全；同一实例里有几个被排除的段，各管各的窗口。缺口两头在同一段里的直接记给那一段。实例开头缺的块、探针报告的丢弃数比缺口多出来的尾部丢块（也含丢掉的事件）同样按这个办法归属。尾部丢块 = 探针报告的丢弃数减去文件里所有缺口的总数，所以**所有缺口都要计入总数**，包括不归任何格的：早于第一个 `C` 行的孤块之间的缺口（以及第一个块就是孤块时它之前缺的块）属实例级，不归任何格，不当成尾部丢块记给最后一格，也不记给第一格，只在「提示」里单独报个数（缺几个块序号、几处）。输出的「提示」逐实例写出归给两边的个数。
- 摘要线程被宿主占住、`C` 行之前没有摘要行可用时，缺失的块序号无从归属，各个未排除的段都按数据不全处理。

已知限制：摘要每秒一条，窗口边界只精确到 1 s。两格紧挨着、中间没有空闲时，前一格最后不到 1 s 内的丢块会归给后一格：后一格未排除时让它数据不全（宁可多判不全）；后一格被排除时，这部分丢块随它被吞掉，前一格的丢块就看不见了。这种情形不要靠 `--exclude`，整节重采。丢掉的事件（不是块）不占 `seq`，摘要里的累计丢弃数却含它们，归属会因此偏几个；探针报告的丢弃数比缺口多出来的部分一律当作最后一个块之后的尾部丢块，最后一格恰好被排除时，这部分连同中途丢掉的事件会随它被吞掉。指定的文件或 `C` 行不存在、指向不唯一、或重复指向同一个 `C` 行，退出码是 5（`--crashed` 指向的东西对不上也是 5）。

**格观察**不带 A 编号、不阻断，`--json` 里是单独的 `observations` 键。它逐格给出类别 2 / 3 的本格证据，并把采到的数据算出来，对应计划里不在 A1 至 A9 内的几项，只观察不判定：

- 同通道顺序：所有类别 1 的格里，两端按 `mono_ns` 最近邻配成对之后，按 `call_seq` 是 In 先于 Out 的回调占比（`order.in_first` / `order.pairs`）。
- A1 的 Out 端起播时间线停顿（`a1_stall`）：逐个稳态格给最长停顿的毫秒数与块数、播放段数，上限见 A1 的说明。
- 实例替换（`replaced`）：`disable-track` 格里每个写了 `destruct` 的旧实例，给角色、新实例 `set_state` 与 `paired` 离析构的毫秒数（没出现或没配对是空）。
- 旁路（`bypass-in`、`bypass-out`）：两端 `bypassed` 为 1 的块数，即走了 `processBlockBypassed` 的块；Output 的 `w` 按 `seq` 排序后相邻两块的停滞次数（相等且上一块的 `n` 不为 0；0 样本回调不推进写头）、回退次数（变小）与跳变次数（差为正却不等于上一块的 `n`）。
- Smart（`smart`）：In 端块之间最长的回调间隙（ms）、重同步总次数（`rs` 之和，其中含 stall_resume，日志不区分原因，解读时要结合该格没有别的重同步来源）、`ping` 条数。
- 错放（`misplaced-*`）：两端都有块时给成对数、In 先于 Out 的数、hostNs 相等的数和两端 `off` 的取值；只有一端有块写「无法判断」。

**rename 格**没有任何 `track_props` 事件时判 A6 数据不全，而不是当没有这一格：契约要求每个 `C` 行之后补写一条快照。

**冻结条件 F1 的 variant 覆盖。** F1 所列 case 里，下面这些 variant 各至少要有一格得出本格证据，缺哪个就在 F1 行里点名（`CB-04` 的 `dop` 是可选项，不强制；`CB-04` 的 `export-offline` 与 `LU-04` 的 `export-offline` 或 `bounce` 由 A3 要求）：

- `CB-05`：`bypass-out` `bypass-in` `deactivate` `disable-track`
- `CB-04`：`rip` `freeze`

`rip`、`freeze` 的格观察里列出实例日志数，宿主是否克隆实例就看这个数。

**冻结条件 F1** 要求：`CB-01`、`CB-02`、`CB-04`、`CB-05`、`LU-02`、`LU-03`、`LU-04` 都有能下结论的数据且无缺口（`CB-04`、`LU-04` 可只靠导出比对行，`LU-02` 看配对与后端事件，其余要有块）；`CB-01` 的 12 格与 `LU-03` 的 3 格稳态矩阵一格不缺；没有无法归格的块、没有同键重复（只看上述 case 里类别 1 的格）；F1 所列 case 的格观察没有数据不全；A1 至 A8 都有结论。F2 至 F4 由人确认。

## 退出码与机读字段

| 退出码 | 含义 |
|---|---|
| 0 | A1 至 A9 全部通过，且 F1 满足 |
| 1 | 有不通过 |
| 2 | 输入取值不合格式，或用法错误 |
| 3 | 没有不通过，但有数据不全，或 A1 至 A9 虽然都过、F1 因缺数据没满足 |
| 4 | 内部错误 |
| 5 | `--exclude` 指定的文件或 `C` 行不存在，或指向不唯一，或重复指向同一个 `C` 行；`--crashed` 指定的文件不存在、重复，或标注的实例其实有收尾行（参数指向的东西对不上，与 2 的写法或格式错误分开） |

F1 因判据不通过而不满足时退出码是 1。现场先跑一次（宿主还开着）时 A8 与 F1 不作数，退出码多半是 3，只看 A1 一行。`--json` 输出里 `stop` 为真表示 A1 不通过，要停工上报（被排除的段里本来就不通过的项也算）；`toggles` 回显 `--toggles` 的现场次数；`crashed` 列出被 `--crashed` 标注的实例序号与角色；`items[].verdict` 取 `PASS` / `FAIL` / `INCOMPLETE`；`f1`、`warnings`、`extras` 同 Markdown 输出里的对应段。
