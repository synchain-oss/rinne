# Rinne 用户指南

## 使用前必读

反馈可能在一瞬间变得很响。Rinne 的用途就是把一条通道接回自己。请从反馈量 0 开始，试验时把监听音箱和耳机调小，并保持安全保护开启。Rinne 会对回送信号做限幅和异常值清理，也有紧急切断（Panic），但放在环路里的插件仍可能抬高送到音箱的电平；任何软件都无法保证环路永远不啸叫。本软件不提供任何担保（GPL-3.0 第 15–16 条）。

1. **放置位置**：Rinne Input 插在通道插入链的第一格；Rinne Output 插在你想放进环路的最后一个插件之后、推子分隔线之上（最简单：推子前区最后一格；宿主没有推子前区时，插在插入链最后一格）。两者之间的插件，包括宿主自带的插入效果器，都在环路里，它们自身的延迟会叠加到环路延迟 D 上；Output 之后的插件、推子、声像和发送都不在环路里。
2. **从 0 开始**：新实例的反馈量是 0，加载工程或预设时回送从 0 淡入。先调低监听音量，再从 0 慢慢往上调：回送越多越容易自激。混合在 50% 及以上、环路里没有衰减时，反馈超过 100% 一定会自激；环路里的插件带增益（EQ 提升、压缩补偿、饱和）时，更低也可能自激。限制器和失控保护默认开启，但挡不住长时间的高电平。
3. **出事先切断**：听到啸叫或异常，先按「紧急切断」：它只切断回送，干声照常通过；恢复请点提示条里的「恢复回送」。窗口关着时，最快的办法是在宿主里旁路 Rinne Input。推子不在环路里，只拉推子只是听不见，环路仍在增长；停止播放和静音也停不住自激。
4. **一组一对**：一个组（A–H）只放一个 Rinne Input 和一个 Rinne Output，两端组号一致才会连接。复制轨道会连组号一起复制：副本会显示「冲突」，在副本的 Rinne Input 上点「移到空闲组」，再在副本的 Rinne Output 上点「重新配对」。

## 安装

下载和安装步骤（包括 macOS 上多出来的解锁一步）见 [INSTALL](INSTALL.md)。两个插件都要装，版本必须相同，然后在宿主里重新扫描插件。哪些宿主看过、看到什么程度，见[宿主兼容性](DAW_COMPATIBILITY.md)。

## 五分钟上手

1. 选一条有声音的通道，把 Rinne Input 插在插入链第一格。
2. 在它后面放你想纳入环路的插件（延迟、滤波、失真都行），再把 Rinne Output 放在其中最后一个之后、推子分隔线之上。
3. 看两个插件的指示灯，应该显示「已连接」。没有的话见下面的「配对」。
4. 先把监听音量调低。开始播放，稍等一下：起播时环路会被清空，回送要至少绕一圈环路延迟 D 才会回来。
5. 一边听一边把反馈量从 0 慢慢加上去。按口味设置环路延迟 D 和混合。
6. 听到不对劲，先按「紧急切断」（它只切断回送），或者在宿主里旁路 Rinne Input。

## 放置位置与环路的边界

Rinne Input 是返回端：它读回从环路里回来的信号，混进通道里。Rinne Output 是发送端：它把宿主的音频原样直通，同时复制一份送进环路。两者之间就是环路。

| 位置 | 放什么 | 在环路里吗 |
|---|---|---|
| 插入链第一格 | Rinne Input | 环路的起点 |
| 它后面的格子 | 你想纳入环路的插件，包括宿主自带的插入效果器 | 在 |
| 其中最后一个之后 | Rinne Output | 环路的终点 |
| Rinne Output 之后的格子 | 其他任何东西 | 不在 |
| 推子、声像、发送 | 调音台控件 | 不在 |

Rinne Output 要放在插入链的推子分隔线之上（最简单：推子前区最后一格）。宿主没有推子前区时，用插入链最后一格。环路里每个插件的延迟都会叠加到环路时间上，所以信号绕一圈要 D 加上这些延迟。

Rinne Output 还必须在 Rinne Input 之后。顺序反了，提示条会说「插件顺序反了：把 Rinne Output 移到环路最后一个插件之后。」

## 配对

两个插件通过组（A 到 H）找到对方。只有两端在同一个组才会连接，一个组只放一个 Rinne Input 和一个 Rinne Output。新插入的插件会自己挑一个组（新的 Rinne Output 跟随最近一个未配对的 Rinne Input，同名轨优先）并标上「自动」；点任意组可以改为手动。

组那一行下面，Rinne 会显示它能看到的轨道名：「轨道名一致」「轨道名不同」或「无法核验」。名字一致说明两端很可能在同一条轨上。宿主不给轨道名也没关系，只是 Rinne 无法核对。

指示灯告诉你配对到了哪一步：

| 指示灯 | 含义 | 怎么办 |
|---|---|---|
| 已连接 | 环路闭合，两端都找到了 | 不用管 |
| 已连接（未核验） | 已连接，但宿主没有提供轨道名 | 不用管，不影响使用 |
| 等待音频 | 宿主还没有送来音频 | 开始播放 |
| 未找到 Output（在 Input 上）、未找到 Input（在 Output 上） | 这个组里没有对方 | 插入对方并选同一个组 |
| 冲突 | 这个组已经有另一个 Input（或 Output） | 在 Input 上点「移到空闲组」，再在 Output 上点「重新配对」 |
| 未分组 | 8 个组都被占用 | 删掉或改组一对 |
| 失联 | 超过 2 秒没有收到对方回应，回送已淡出 | 检查对方插件有没有被旁路或删除 |
| 跨进程 | 两端在不同进程里，延迟可能变化 | 能放在同一条轨上就放在一起 |
| 不同轨道？ | 轨道名不同，环路延迟可能变化 | 确认两端放的位置是你想要的 |
| 版本不匹配 | 两个插件版本不同 | 两个都装同一个版本 |
| 采样率不一致 | 两端的采样率不同，回送已停止 | 让两端用同一个采样率 |
| 无法连接 | 共享内存不可用（例如沙盒宿主），环路关闭，只输出干声 | 沙盒化插件的宿主暂不支持；否则用「复制诊断信息」反馈 |
| 验证模式 | 在插件验证工具里运行，环路关闭 | 不用管，这里本该如此 |
| 已旁路（在 Output 上） | 宿主旁路了 Rinne Output，它在发送静音 | 关掉旁路 |

复制轨道会连组号一起复制。副本会显示「冲突」：在副本的 Rinne Input 上点「移到空闲组」，再在副本的 Rinne Output 上点「重新配对」。如果提示条给出「接管」，说明这个组被一个已停用的实例占着，接管后那个实例会失去这个组。

## Rinne Input 的控件

所有调节都在 Rinne Input 里。从上到下：

- **组**：上面说的 A–H 组。
- **反馈量**：回送的增益，0 到 150%，从 0 开始。拖动调节，Shift 微调，双击复位，Ctrl（mac：Cmd）+ 单击输入数值。超过 100% 表盘变成琥珀色，标签显示「自激区」。回送淡入时显示「淡入中」，被切断时显示「已切断」。限制器关闭时反馈上限是 100%（「设定 120%，有效 100%」）。
- **环路**：开关环路。关闭时回送淡出，环路内容保留。它是宿主参数，可以被自动化，也可以映射到控制器。
- **混合**（干到回送）：干声和回送的平衡。往「干」调，回送被调小；往「回送」调，干声被调小；50% 时两者都是满电平。默认 25%。
- **环路延迟 D**：信号绕环路一圈的时间，1 到 4000 ms。可选「毫秒」「采样」或「节拍」（按宿主速度换算的音符时值，含三连音和附点）。「最小」标记显示可用的最小 D。
- **回送音色**：「低切」（最低处为「关」）、「高切」（最高处为「关」）和「Ø 极性反转」。它们只作用于回送，干声不受影响。
- **安全**：「紧急切断」、带上限的「限制器」（−24 到 0 dBFS，默认 −6）、「增益缩减」表、「直流」「数值」「失控」三盏灯，以及「失控保护」。
- **电平**：「输入」「回送」「输出」三个表。「回送」在反馈增益之前测量，所以反馈为 0% 时它也会动，可以用它确认环路已通。
- **预设**：工厂预设和你自己的预设，见「预设」一节。

## Rinne Output

Rinne Output 没有旋钮。它显示组、配对指示灯、轨道名，以及一行发送状态，例如「发送中 · ST · 48 kHz」。宿主旁路它时显示「旁路：写入静音」，回送为静音。宿主没有调用处理时显示「宿主未调用处理：暂停写入」。

标题下有一条红色的摆放提醒，说明 Rinne Output 该放在哪里。点「知道了」可以关掉它：这个选择记在这台电脑上，对所有 Rinne Output 生效，不存进工程。想让它回来，在「关于」的「高级设置」里打开「显示位置提示」。「插件顺序反了」之类的提示不受影响，照常出现。

它把宿主的音频原样直通，所以把它放进链里不会改变通道的声音。环路里的插件输出 NaN 或 Inf 时，在进入环路的路上被清理：异常值变成 0，并计入 Rinne Input 上的「数值」灯。

## 环路延迟 D

D 是固定的样本数。环路延迟不随缓冲大小和导出方式变化（已在 Windows 上的 Cubase Pro 15 和 macOS 上 LUNA 的 Audio Unit 版本实测，见[宿主兼容性](DAW_COMPATIBILITY.md)），两个插件也都不向宿主上报延迟，所以宿主不会对环路做补偿。

- **最小值。** D 不能低于「宿主声明的最大块长」和「本会话见过的最大块长」中较大的一个。「最小」标记会显示它；它随缓冲设置变化，Cubase 的 ASIO-Guard 会抬高它。设得更小时，Rinne 按最小值运行，并显示「实际」。
- **总延迟。** 环路时间是 D 加上环路里每个插件的延迟（界面上写作「总延迟 = D + 环内插件延迟」）。
- **节拍。** 音符时值跟随宿主速度；拿不到速度时 Rinne 按 120 BPM 计算，并会标出来。
- **改动 D。** 音频播放时改 D，Rinne 会在 40 ms 内在旧延迟和新延迟之间交叉淡化。
- **上限。** D 最大 4000 ms。

## 安全机制

### 回送经过什么

每个送回来的样本都按同一条链处理，顺序是：非有限值清理、直流阻断、低切、高切、极性、反馈增益、电平检查、限制器、软削波、最后再检查一次是否有限。链里任何一环失败，回送都变成 0，干声照常播放。

### 紧急切断与恢复回送

「紧急切断」会立即把回送淡出到 0 并保持切断，干声照常播放。再点一次不会恢复。要恢复，请用提示条里的「恢复回送」，回送会从 0 在 500 ms 内淡入。切断后有约 1.5 秒的短暂等待，之后「恢复回送」才可用。标签显示「已切断」，并写明原因：手动、异常数值、电平过高或失控。

紧急切断是界面里的按钮，不是宿主参数，所以不能映射到控制器。窗口关着时，最快的办法是在宿主里旁路 Rinne Input。

### 淡入

回送从第一个有效样本起在 500 ms 内淡入，只在这几种情形之后：插件第一次准备好、新配对、换了新的写入方、载入预设或宿主恢复保存的状态（工程、A/B、撤销），以及「恢复回送」。新实例的反馈量从 0 开始。

重新打开「环路」、或取消 Rinne Input 的旁路不在其列：没有 500 ms 的淡入，回送会在约 10 ms 内带着环路里还留着的内容回到原来的电平。反馈量调得高时，先调低反馈量，再重新打开「环路」。

### 失控保护

回送持续过载时，「失控保护」会自动降低反馈（每秒 6 dB），平静 3 秒后回升。反馈不超过 90% 且环路里没有增益时，它不会介入。降到 −24 dB 仍止不住时，它会切断回送。回送电平持续 100 ms 在 +12 dBFS 以上，会切断回送并清空环路。Rinne Input 内部出现 NaN 或 Inf，会立刻切断并清空环路。

### 需要知道的限制

中等环路增益下的稳态自激会被压在限制器上限，失控保护不会介入，长时间的高电平也没有东西能拦住。电平很高、谐波丰富的干声可能触发 +12 dBFS 检查。这些以及其他限制列在 [KNOWN_ISSUES](KNOWN_ISSUES.md)（中英双语）。

## 导出、渲染与冻结

- **环路时间相同。** D 是固定的样本数，所以离线导出和实时播放用的是同一个环路时间。Rinne 的声音处理不看宿主是否在离线渲染，只在监视导出问题时用到这一信息。
- **干净起点。** 默认情况下，起播时环路会被清空（「关于」里「高级设置」下的「起播时清空环路」），所以每次播放或导出都从空环路开始。
- **开头的淡入。** 工程刚加载、配对后约 0.5 秒内就开始的导出，开头的回送是淡入的，与之后的实时播放不同。这是上面那条淡入规则的代价。加载或重新配对之后，等一秒再导出。
- **导出提示。** 宿主越过它自己的限制时，提示条会写「上次导出可能与播放不同」，并给出原因：块长超限、D 小于块长、Output 端宿主越限，或环路中途重新对齐过。调大 D 再导出。
- **冻结与就地渲染。** 在 Windows 上的 Cubase Pro 15 里两者都测过：渲染出的回声与普通导出一致，Cubase 会把冻结文件里的静音段省掉，所以它比时间线短。其他宿主怎么处理配好对的插件，还没有测过。请听结果，并与普通导出对比。

## 宿主设置

### Cubase

Rinne Input 插在第一格。Rinne Output 放在同一条通道的推子分隔线之上（推子前区最后一格最简单）。ASIO-Guard 会抬高最小 D，「最小」标记会显示抬高了多少。Windows 上的 Cubase Pro 15 在预览构建上通过了书面验收测试，两者之间的 Cubase 自带插入效果器在环路里；详情见[宿主兼容性](DAW_COMPATIBILITY.md)。

### LUNA

LUNA 默认没有启用 VST3 扫描，想用 VST3 版本要先把它打开。LUNA 只列系统级文件夹里的 VST3，所以要用 `install-macos.sh --system` 安装（按默认方式装过的，先运行 `uninstall-macos.sh`），步骤见 [INSTALL](INSTALL.md#macos)。也可以用 Audio Unit 版本（beta），它不需要 `--system`。LUNA 有第一份 Audio Unit 版本的部分测试记录，仍有一个发现未解决：见[宿主兼容性](DAW_COMPATIBILITY.md)。

### 其他宿主

其他宿主都还没有测过。放置规则和界面里的提示在哪里都一样。如果看到不对劲的地方，请复制诊断信息（见「界面」）并反馈。

## 界面

- **首次运行。** 先出现语言卡片，然后是使用规则页。点「我已了解，开始导览」看一遍简短的导览，或点「跳过导览」。
- **语言。** 用「中」「EN」「FR」三个按钮切换。
- **重看规则和导览。** 点右下角的问号按钮。
- **缩放。** 选一个缩放级别；Rinne 会应用它，并要求你在 10 秒内点「保存」确认，否则回退；点「取消」同样回退。WebKit 低于 26.4 时缩放固定为 100%。
- **关于。** 点版本号查看许可、高级设置（起播时清空环路、Tail 模式：自动、无限或 30 秒、记录诊断日志；Rinne Output 上还有显示位置提示）、复制诊断信息和查看使用规则。

Tail 模式告诉宿主尾音有多长，防止宿主在静音时挂起插件、把环路断开。自动的意思是 VST3 无限、Audio Unit 30 秒。

## 预设

「预设」里有「工厂预设」和「我的预设」。「保存为新预设…」会保存当前设置；预设可以在同一个菜单里覆盖或删除。名称不能包含 \ / : * ? " < > |。预设不含环路开关、组号、限制器开关与上限。载入预设时，回送从 0 淡入。

## 隐私与磁盘上的文件

Rinne 本身不发起任何网络连接，不需要账号，也不收集任何数据。它只写下面这些文件：

- 界面默认值（语言、已确认使用规则、已关闭的导览、缩放）：Windows 上是 `%APPDATA%\Synchain\Rinne\` 下的 `ui-defaults.settings`，macOS 上是 `~/Library/Application Support/Synchain/Rinne/`。
- 你的预设：同一位置旁边的 `Presets` 文件夹。
- 仅 Windows：WebView2 的用户数据，在 `%LOCALAPPDATA%\Synchain\Rinne\WebView2`。
- 仅 macOS：配对用的一个小锁文件夹，`~/Library/Application Support/Synchain/Rinne/ipc`。
- 诊断日志，只有打开「记录诊断日志」才会写（默认关）：Windows 上在 `%LOCALAPPDATA%\Synchain\Rinne\logs\`，macOS 上在 `~/Library/Logs/Synchain/Rinne/`，每个插件一个文件，到 1 MiB 轮转。
- 「查看许可证」会把 `Rinne-LICENSE.txt` 写到临时文件夹并打开它。

「复制诊断信息」只是把文字放进剪贴板，不会发送任何东西。内容有版本、系统、宿主、音频设置和环路状态，不含文件路径或用户名；轨道名只给是否一致，外加一个 8 位散列。没有 GitHub 账号的话，可以把它发到 contact@synchain.ca。

## 故障排查

### 听不到回送：五步排查

1. **看指示灯。** 两个插件都应该显示「已连接」。不是的话，按上面「配对」里的表处理。
2. **读提示条。** 它会告诉你回送为什么是静音：已紧急切断、环路已关闭、宿主旁路了本插件、Rinne Output 被宿主旁路、宿主暂停了处理，或者被切断。标签显示「已切断」时，点「恢复回送」。
3. **查反馈量和混合。** 反馈量从 0 开始，为 0 时回送什么也不加。把它调高一点。确认「混合」没有拉到「干」那一端。「回送」表在反馈为 0% 时也会动，它动了就说明环路已通。
4. **查顺序。** 先是 Rinne Input，然后是你想纳入环路的插件，最后是 Rinne Output，且在推子分隔线之上。留意「插件顺序反了」和轨道名相关的提示。
5. **等一圈。** 起播会清空环路，所以回送要至少过 D 才会回来。然后看有没有采样率、块长和沙盒相关的提示。还是没声音的话，用「复制诊断信息」并反馈。

### 把「环路」映射到快速控制

界面上的「环路」开关在宿主里是名为「Loop」的参数（宿主里不分语言都显示这个名字），所以多数宿主允许把它指派给控制器上的按钮；Cubase 叫快速控制，其他宿主叫远程控制或 MIDI 学习。把按钮设成按下时关闭环路，这样按一下回送就淡出。再按一次，回送会在约 10 ms 内回来，没有 500 ms 的淡入，所以反馈量调得高时先调低它。

要清楚它是什么、不是什么。环路关闭只是让回送淡出，不会锁存，也不会清空环路，再把环路打开，回送就回来。真有麻烦时请用「紧急切断」：它会切断并清空，且需要「恢复回送」。紧急切断本身不能映射。

### 其他症状

- **啸叫或快速堆积。** 按「紧急切断」，调低反馈量，再检查环路里哪个插件加了增益。
- **环路比 D 长。** 环路里的插件会把它们自己的延迟叠加到 D 上。
- **导出的开头静音或不对。** 见「导出、渲染与冻结」。
- **只看到一个简易面板。** Microsoft Edge WebView2 运行时缺失或过旧、或界面启动失败时，Rinne 会显示一个简易面板。面板上的 Panic、Resume 和 Loop 按钮不依赖界面也能用，但只在 Rinne Input 上可用，Rinne Output 的面板上它们是禁用的。点 Install WebView2 Runtime 或 Retry。

## 常见问题

- **为什么反馈量从 0 开始？** 因为环路可能涨得非常快。新实例、新配对和载入预设都从 0 开始。
- **Output 能放在另一条轨上吗？** 可以，但延迟可能因此变化，界面会提示。
- **Rinne 会给宿主增加延迟吗？** 不会：两个插件都不上报延迟，宿主不会做任何移位。环路本身需要 D 加上其中插件的延迟。
- **问题往哪里反馈？** 项目的 issue 页面；没有 GitHub 账号的话，发邮件到 contact@synchain.ca。
- **macOS 版签名了吗？** 没有。它没有 Apple Developer ID 签名，也未经公证，见 [INSTALL](INSTALL.md)。
- **能用在商业作品里吗？** 能。GPL 管的是软件的复制与分发，不管你用它做出来的音频。
- **为什么不能映射紧急切断？** 它按设计是界面动作；要做硬件急停，请映射「环路」。

## 术语表

- **干声**：从宿主进入 Rinne Input 的信号。
- **回送**：绕环路一圈回来的信号，经过回送音色和反馈增益处理。
- **环路延迟 D**：信号绕环路一圈的固定时间。
- **组**：A–H 之一，把一个 Rinne Input 和一个 Rinne Output 配成一对。
- **自激**：回送和喂给它的信号一样响或更响，环路自己维持并增长。
- **Tail**：输入停止后，插件告诉宿主自己还会继续发声多久。
- **推子前区**：调音台通道里推子分隔线之上的插入格。
